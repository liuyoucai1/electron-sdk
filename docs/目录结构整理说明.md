# 目录结构整理说明

更新时间：2026-06-13

## 本轮已明确的边界

### `src/shared`

放跨业务、跨页面、无业务流程依赖的公共能力。这里的代码不能直接依赖 `views`、`stores` 或路由。

- `src/shared/assets/`：通用资源处理，如图片 base64、Blob URL、资源释放。
- `src/shared/html/`：通用 HTML 文本转义与净化。
- `src/shared/utils/`：纯函数工具，如答案分布判断、数字答案清洗。

本轮已迁入：

- `src/shared/assets/resolveImageSrc.js`
- `src/shared/html/sanitizeHtml.js`
- `src/shared/utils/answerDistribution.js`
- `src/shared/utils/numericAnswer.js`

### `src/api`

只放前端访问 Electron IPC、本地服务或后端能力的封装。可以依赖 `shared`，不能依赖 `views` 内部工具。

本轮已修正：`src/api/sessionAsset.js`、`src/api/screenshot.js` 不再引用主观题目录下的图片工具。

### `src/views/<业务>`

只放页面、业务组件、业务 composable 和业务数据组装逻辑。业务目录可以依赖 `shared`，但公共工具不能反向依赖业务目录。

暂时保留：

- `src/views/ask/subjective/utils/buildAnswerProgressSession.js`
- `src/views/ask/subjective/utils/buildReadReciteSession.js`
- `src/views/ask/subjective/utils/buildVoiceAnalysis.js`

这些仍包含“问业务 / 主观题”上下文，不适合直接放到 `shared`。

### `src/components`

放跨页面复用的 UI 容器和宿主能力。`components/widget` 继续负责窗口宿主、缩屏布局和 widget 注册。

本轮已优化：`widgetRegistry.js` 改为异步组件注册，避免一进入应用就加载所有业务 widget。

新增公共组件：

- `src/components/distribution/AnswerDistributionList.vue`：统一作答分布、进度条、学生名单展开和图例展示。

业务侧保留薄封装：

- `src/views/ask/components/ObjectiveQuestionDistribution.vue`
- `src/views/ask/subjective/components/ReadReciteScoreDistribution.vue`

薄封装只负责传入业务差异，例如“客观题答案正误状态函数”或“背读分数段 status”。

### `src/plugins`

放应用启动级插件注册。`src/main.js` 只做应用创建、Pinia、Router、插件安装和样式入口引入。

本轮新增：

- `src/plugins/elementPlus.js`：只注册项目实际使用到的 Element Plus 组件和样式，避免 `main.js` 全量 `use(ElementPlus)`。

### `src/stores/flow.js`

`flowStore` 仍是问业务流程真相来源，但本轮已把原来单个巨大的 `handleAskWidgetAction()` 拆成：

- 顶部动作分发表 `ASK_ACTION_HANDLERS`：只负责把组件发来的 `action` 映射到具体 store action。
- 顶部路由/步骤表：`ANSWER_PROGRESS_ENTRY_TARGETS`、`FINISH_ANSWERING_TARGETS`、`FULLSCREEN_ROUTE_STEPS`、`READ_RECITE_COMPACT_ROUTES`。
- 小型 action 方法：如 `openAnswerProgress()`、`finishAnswering()`、`startVoiceQuestion()`、`finishAnswerProgress()` 等。
- 通用返回构造方法：`openSmallPage()`、`openFullscreen()`、`createSmallPageTarget()`。

新增流程动作时优先做三件事：在分发表注册 action、增加一个小 action 方法、必要时补路由表。不要再把新分支塞回 `handleAskWidgetAction()` 里面。

本轮新增行为测试：

- `tests/stores/flow.test.mjs`：覆盖答题入口、多题结束跳转、语音分析页补题返回分析页等关键链路。

## 后续建议

1. 继续把 `flowStore` 中问业务以外的纯状态保存方法按领域分组，后续可拆到 `src/stores/ask/` 子模块。
2. 等真实数据接入后，把 `src/mock` 改成 development-only fixture，禁止正式业务链路直接 import mock。
3. 如果问业务继续扩张，可考虑新增 `src/features/ask/`，把 `views/ask` 中非路由页面的业务 composable、业务组件逐步迁入 feature 目录；路由页面仍保留在 `src/views/ask`。
