# 小屏组件与全屏页面流程架构

> 目标：统一管理 EZ Quiz 桌面端中的小屏组件、缩屏组件、最小化按钮、全屏页面和单条业务线路状态。

## 1. 核心结论

本项目不应把小屏页面写成 `el-dialog`，也不应把所有业务步骤都写成路由页面。

推荐模型：

```text
小屏 / 缩屏 / 最小化：由 App.vue 挂载 WidgetHost 统一管理
全屏页面：使用 Vue Router 管理
业务流程：由 Pinia 控制单条线路
业务数据：通过 Pinia action 调 api 层，后续 api 层可切换 IPC / HTTP / 单机数据源
```

整体分层：

```text
App.vue
  ├─ ClassroomLauncher       启动课堂
  ├─ FloatingBall / 胶囊      无业务流程时显示
  ├─ WidgetHost              所有小屏、缩屏、最小化组件宿主
  └─ RouterView              全屏页面出口
```

## 2. 基本原则

### 2.1 小屏不是弹框

小屏组件是桌面 widget，不是弹框。

它们应具备：

- 独立尺寸
- 固定比例
- 可拖动
- 可最小化
- 可关闭
- 可根据 DPI / 分辨率缩放
- 可上报 Electron 交互区域

所以小屏组件统一交给 `WidgetHost + WidgetShell` 管理。

### 2.2 全屏才走路由

全屏页面继续使用 Vue Router。

原因：

- 全屏页面有完整页面生命周期
- 可通过 `route.meta.fullscreen` 控制 Electron 全屏交互状态
- 可隐藏小屏、胶囊和悬浮球
- 页面销毁、关闭、返回逻辑更清晰

### 2.3 Pinia 负责流程真相

业务流转判断不要散落在组件里。

组件只做：

- 展示
- 点击按钮
- 调用 store action

Pinia 负责：

- 当前业务线是什么
- 当前步骤是什么
- 当前显示形态是什么
- 下一步去哪里
- 结束答题后进入哪个页面
- 关闭后如何清理
- 缩屏、最小化、全屏如何切换

## 3. 推荐目录结构

```text
src/
  stores/
    flow.js                 流程状态：线路、步骤、显示形态、id、nextStep
    widget.js               小屏窗口状态：位置、尺寸、缩放、zIndex、最小化
    ask.js                  问业务数据：答题中、单题分析、多题分析等
    test.js                 测业务数据
    analysis.js             析业务数据

  api/
    ask.js                  问相关接口封装，内部可走 IPC / HTTP / 本地单机数据
    test.js
    analysis.js

  components/
    widget/
      WidgetHost.vue        渲染所有小屏 widget
      WidgetShell.vue       拖动、缩放、尺寸、zIndex、交互区域上报
      widgetRegistry.js     小屏组件注册表

    flow/
      FlowMinimizedButton.vue

    flow/compact/
      AnsweringCompact.vue
      SingleAnalysisCompact.vue
      MultiAnalysisCompact.vue
      QuestionAnalysisCompact.vue

  views/
    ask/
      AskFullscreenView.vue
      fullscreenRegistry.js
```

## 4. 状态设计

### 4.1 flowStore

`flowStore` 只保存“足够恢复当前线路的最小状态”。

示例：

```js
{
  activeFlow: 'ask',
  currentStep: 'answering',
  viewMode: 'compact',

  sessionId: 'session-001',
  questionId: 'question-001',
  batchId: null,
  currentQuestionIndex: 0,

  nextStep: 'single-analysis',
  nextViewMode: 'fullscreen'
}
```

字段说明：

| 字段 | 作用 |
| --- | --- |
| `activeFlow` | 当前业务线，如 `ask` / `test` / `analysis` |
| `currentStep` | 当前业务步骤，如 `answering` / `single-analysis` |
| `viewMode` | 当前显示形态：`idle` / `compact` / `minimized` / `fullscreen` |
| `sessionId` | 当前提问或答题会话 id |
| `questionId` | 当前题目 id |
| `batchId` | 多题批次 id |
| `currentQuestionIndex` | 多题内部当前题目索引 |
| `nextStep` | 当前步骤完成后进入哪个业务步骤 |
| `nextViewMode` | 当前步骤完成后用什么形态展示 |

### 4.2 widgetStore

`widgetStore` 负责小屏桌面窗口状态。

如果当前只允许单条线路，可以先维护一个 `activeWidget`。

示例：

```js
{
  activeWidget: {
    id: 'ask-answering',
    type: 'answering',
    mode: 'compact',
    x: 1200,
    y: 120,
    width: 400,
    height: 800,
    minWidth: 360,
    minHeight: 640,
    zIndex: 10,
    scale: 1,
    props: {
      sessionId: 'session-001'
    }
  }
}
```

后续如果要支持多个小屏同时渲染，可以把 `activeWidget` 扩展为 `widgets: []`。

## 5. 小屏组件渲染方式

### 5.1 WidgetHost

`App.vue` 不直接认识具体小屏组件，只挂载 `WidgetHost`。

```text
App.vue
  -> WidgetHost
    -> WidgetShell
      -> 动态业务组件
```

`WidgetHost` 根据 `widget.type` 从注册表取组件。

示例映射：

```js
const widgetRegistry = {
  answering: AnsweringCompact,
  'single-analysis': SingleAnalysisCompact,
  'multi-analysis': MultiAnalysisCompact,
  'question-analysis': QuestionAnalysisCompact
};
```

### 5.2 WidgetShell

`WidgetShell` 统一处理非业务能力：

- 拖动
- 定位
- 固定比例缩放
- z-index
- 最小化
- 关闭
- DPI / 分辨率适配
- 交互区域上报

业务组件不要自己实现拖动和 DPI。

### 5.3 业务组件

业务组件只负责内容。

例如 `AnsweringCompact.vue`：

- 展示答题进度
- 展示当前题目信息
- 点击“结束答题”时调用 `finishAnswering()`

它不判断结束后去单题分析还是多题分析。

## 6. 固定比例与 CSS 写法

推荐采用“设计稿 px + 外层统一缩放”的方式。

业务组件内部按设计尺寸写，例如 400 x 800：

```scss
.answering-compact {
  width: 100%;
  height: 100%;
  padding: 24px;
  background: #ffffff;
  overflow: hidden;
}
```

`WidgetShell` 负责把设计尺寸缩放到真实屏幕。

推荐结构：

```text
widget-frame          真实屏幕尺寸，负责定位和占位
  widget-design-canvas 设计稿尺寸，通过 transform: scale(...) 缩放
    业务组件            永远工作在固定设计尺寸内
```

这样每个小屏组件可以稳定使用 px，不需要每个组件单独适配 DPI。

## 7. 全屏页面渲染方式

全屏页面使用 Vue Router。

推荐保留一个问业务全屏承载页：

```text
/ask/fullscreen
```

页面内部根据 `flowStore.currentStep` 渲染不同全屏组件：

```text
AskFullscreenView
  -> single-analysis fullscreen
  -> multi-analysis fullscreen
  -> question-analysis fullscreen
```

如果后续全屏页面差异很大，也可以拆多个路由，但业务数据仍从 Pinia / api 层读取，不存到路由组件本地。

## 8. 全屏、缩屏、最小化、关闭规则

### 8.1 关闭

关闭代表断开整条业务链路。

适用场景：

- 全屏页面点击关闭
- 缩屏页面点击关闭
- 业务异常需要重新开始

行为：

```text
resetFlow()
clearWidget()
router.replace('/')
显示胶囊 / 悬浮球
```

注意：关闭业务链路一般不结束课堂，只清空 `flowSession`，保留 `classSession`。

### 8.2 缩屏

缩屏不清理业务链路。

行为：

```text
flowStore.viewMode = 'compact'
widgetStore.openWidget(...)
router.replace('/')
```

路由关闭后，数据仍在 Pinia 里，`WidgetHost` 根据当前状态渲染对应小屏。

### 8.3 最小化

最小化不清理业务链路。

行为：

```text
flowStore.viewMode = 'minimized'
widgetStore.minimize()
```

界面只显示右侧激活按钮。

点击激活按钮：

```text
flowStore.viewMode = 'compact'
widgetStore.restore()
```

### 8.4 回到全屏

缩屏点击全屏：

```text
flowStore.viewMode = 'fullscreen'
router.push('/ask/fullscreen')
```

业务状态不变，只切换显示形态。

## 9. 答题流程示例

### 9.1 单选题

```text
点击单选
  -> flowStore.startSingleChoiceAnswering()
  -> currentStep = 'answering'
  -> viewMode = 'compact'
  -> nextStep = 'single-analysis'
  -> nextViewMode = 'fullscreen'
  -> WidgetHost 显示 AnsweringCompact

点击结束答题
  -> flowStore.finishAnswering()
  -> currentStep = 'single-analysis'
  -> viewMode = 'fullscreen'
  -> router.push('/ask/fullscreen')

全屏点击缩屏
  -> viewMode = 'compact'
  -> router.replace('/')
  -> WidgetHost 显示 SingleAnalysisCompact

缩屏点击关闭
  -> resetFlow()
  -> clearWidget()
  -> 显示胶囊 / 悬浮球
```

### 9.2 多题提问

```text
点击多题提问
  -> currentStep = 'answering'
  -> viewMode = 'compact'
  -> nextStep = 'multi-analysis'
  -> nextViewMode = 'fullscreen'

点击结束答题
  -> currentStep = 'multi-analysis'
  -> viewMode = 'fullscreen'

多题分析点击内部单题
  -> currentStep = 'question-analysis'
  -> currentQuestionIndex = n
  -> viewMode 保持 fullscreen 或 compact

单题分析点击下一题
  -> currentQuestionIndex += 1

点击缩屏
  -> viewMode = 'compact'
  -> WidgetHost 根据 currentStep 显示 QuestionAnalysisCompact
```

## 10. 结束答题按钮应该怎么写

组件不要判断跳哪里。

错误方向：

```js
if (type === 'single') {
  router.push('/single-analysis');
} else if (type === 'multi') {
  router.push('/multi-analysis');
}
```

正确方向：

```js
const target = await flowStore.finishAnswering();
navigateByTarget(target);
```

进入答题进程前，提前写好下一步：

```js
startSingleChoiceAnswering() {
  this.currentStep = 'answering';
  this.viewMode = 'compact';
  this.nextStep = 'single-analysis';
  this.nextViewMode = 'fullscreen';
}
```

结束答题时只消费 `nextStep`：

```js
finishAnswering() {
  this.currentStep = this.nextStep;
  this.viewMode = this.nextViewMode;

  this.nextStep = null;
  this.nextViewMode = null;

  return {
    step: this.currentStep,
    viewMode: this.viewMode,
    route: this.viewMode === 'fullscreen' ? '/ask/fullscreen' : '/'
  };
}
```

## 11. 数据获取方式

### 11.1 小屏组件如何获取数据

小屏组件从业务 store 读数据，通过 action 确保数据存在。

示例：

```js
onMounted(() => {
  askStore.ensureAnsweringData(flowStore.sessionId);
});
```

如果同一个组件实例不会销毁，监听关键 id：

```js
watch(
  () => [flowStore.currentStep, flowStore.viewMode, flowStore.sessionId],
  () => {
    if (flowStore.currentStep === 'answering' && flowStore.viewMode === 'compact') {
      askStore.ensureAnsweringData(flowStore.sessionId);
    }
  },
  { immediate: true }
);
```

### 11.2 全屏页面如何获取数据

全屏页面可以使用生命周期函数。

```js
onMounted(() => {
  askStore.ensureCurrentStepData();
});
```

也可以监听 `currentStep` / `questionId` / `batchId`：

```js
watch(
  () => [flowStore.currentStep, flowStore.questionId, flowStore.batchId],
  () => askStore.ensureCurrentStepData(),
  { immediate: true }
);
```

### 11.3 Pinia 里的数据职责

建议拆分：

```text
flowStore
  流程状态和跳转判断

widgetStore
  小屏窗口的位置、尺寸、缩放、最小化

askStore / testStore / analysisStore
  业务数据缓存、loading、error、接口请求
```

不要把全部数据都塞进 `flowStore`。

## 12. API 与单机版兼容

组件不要直接关心数据来自哪里。

统一路径：

```text
组件
  -> Pinia action
    -> api 层
      -> IPC / HTTP / 本地单机数据
```

后续支持单机版时，只需要替换 api 层内部实现。

例如：

```text
联网版：api.ask.getAnsweringSession -> HTTP
单机版：api.ask.getAnsweringSession -> IPC -> 本地 Node / SQLite / 文件
```

组件和流程 store 不需要大改。

## 13. 避免闪动的规则

动态小屏切换时，注意避免闪动：

- `WidgetShell` 尽量保持稳定，不跟随业务组件反复销毁
- 打开 widget 前一次性写入 `type / width / height / x / y / props`
- 不要先渲染默认尺寸，再异步改真实尺寸
- 数据未加载时在固定外壳内显示 loading / skeleton
- DPI / scale 统一在 `WidgetShell` 或 `widgetStore` 计算
- resize 时节流更新 scale 和位置
- 业务组件内部不要通过内容撑开外壳尺寸

推荐：

```text
外壳尺寸稳定
内部内容变化
业务数据异步加载
```

不要：

```text
外壳跟着内容高度变化
组件先显示默认大小再跳到真实大小
每个组件自己计算 DPI
```

## 14. 开发落地顺序

推荐按以下顺序改造：

1. 建立 `flowStore`
   - 定义 `activeFlow`
   - 定义 `currentStep`
   - 定义 `viewMode`
   - 定义 `sessionId / questionId / batchId`
   - 定义 `nextStep / nextViewMode`

2. 建立 `widgetStore`
   - 管理当前小屏的 `type / x / y / width / height / scale / zIndex`
   - 提供 `openWidget / closeWidget / minimize / restore`

3. 建立 `WidgetHost`
   - 只负责根据 `widgetStore.activeWidget` 渲染小屏
   - 不写具体业务判断

4. 建立 `WidgetShell`
   - 实现拖动
   - 实现固定比例缩放
   - 实现边界限制
   - 实现交互区域上报

5. 建立小屏注册表
   - `answering -> AnsweringCompact`
   - `single-analysis -> SingleAnalysisCompact`
   - `multi-analysis -> MultiAnalysisCompact`
   - `question-analysis -> QuestionAnalysisCompact`

6. 建立全屏承载页
   - 使用 `/ask/fullscreen`
   - 根据 `flowStore.currentStep` 渲染全屏内容
   - 提供缩屏、关闭按钮

7. 抽出统一导航方法
   - `finishAnsweringAndNavigate`
   - `shrinkFlowAndNavigate`
   - `expandFlowAndNavigate`
   - `closeFlowAndNavigate`

8. 接入业务数据 store
   - `askStore.ensureAnsweringData`
   - `askStore.ensureSingleAnalysisData`
   - `askStore.ensureMultiAnalysisData`

9. 最后接 IPC / 后端 / 单机数据源
   - 保持组件不直接调用 IPC
   - 统一通过 api 层接入

## 15. 一句话总结

```text
App.vue 只负责挂载宿主。
WidgetHost 负责渲染小屏。
WidgetShell 负责桌面窗口能力。
Pinia flowStore 负责流程判断。
业务 store 负责数据获取和缓存。
RouterView 只负责全屏页面。
关闭是断链，缩屏和最小化不是断链。
```
